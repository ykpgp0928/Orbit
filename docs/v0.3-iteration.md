# Orbit v0.3 完整迭代流程 · 方案 · 清单

**基线：** v0.2.x（多 Widget + Launcher + 长按）  
**主题：** Runtime Contract · Lifecycle · Confidence  
**原则：** 不伤手感 · 每步可运行可回滚 · 证据优先于猜测  

**执行修订（入库前已吸收）：**

1. Phase 0 记录**三个实际入口 URL** + commit SHA + 构建 hash + 测试设备（非“三个域名”叙事）。  
2. Phase 1 **提前** `"type": "module"` 与最小 `test:unit`，保证 LifecycleScope 可证伪。  
3. 架构保留 **Legacy Adapter**（`registerHost(start/getRoot)`）；Definition 与 Instance Registry 分离。  
4. Phase 3：**portal 所有权**——只清理本 instance 创建的外置节点。  
5. Phase 4：配置里**省略已挂载 id ≠ destroy**；仅 `destroy(id)` 释放。  
6. Phase 4：Music `#mp-dock-list` 显隐特判下沉到 Music Instance，去掉 Runtime `id==="music"` 耦合。  
7. Phase 6/8：**npm 发布可选**，不阻塞 v0.3.0；优先 GitHub Release + 静态 Demo。  

**总原则：先让 Scope + Clock 销毁测试变绿，再碰 Music。禁止跳过 Clock 试点。**

## 二、版本方案

### 2.1 五个目标

| # | 目标 | 结果 |
|---|------|------|
| 1 | Widget v1 契约 | `register → mount → setVisible → destroy` 可文档化 |
| 2 | 生命周期 | 反复 mount/destroy 无泄漏 |
| 3 | 信心 | 关键路径可自动测；手感靠 Demo + 基线表 |
| 4 | 可发现 | 移动端全隐后仍能打开 Launcher |
| 5 | 性能 | 先 Profile 再改 |

### 2.2 明确不做

多球避让、云同步/商店、React/Vue 重写、默认全页长按、未测量的全面 transform 化、大主题重构、以第三官方 Widget 为成功标准。

### 2.3 架构要点（含 Legacy Adapter）

```text
Orbit Runtime
├── Definition Registry     // register(definition) — 只存定义
├── Instance Registry       // 活实例 + LifecycleScope + destroy
├── Legacy Adapter 层       // v0.2：registerHost({ start, getRoot })
│                            // 内部可包装为“伪 Instance”，逐步迁到 v1
├── Visibility / Events
├── Launcher + Fallback（非 Widget）
└── Storage namespaces
```

| 层 | 职责 |
|----|------|
| **Definition** | id、label、mount 工厂；无 DOM |
| **Instance** | 一次 mount 的结果；持有 `destroy`、可选 `setVisible`/`getVisibilityTargets` |
| **Legacy Adapter** | 现有 Host 仅 `start/getRoot` 时：Runtime 用 adapter 补齐可见性；**不假装已有完整 destroy**，直到 Host 接入 Scope |

| 操作 | 语义 |
|------|------|
| `setVisible(false)` | 隐藏；DOM/状态/资源默认保留 |
| `destroy(id)` | 显式销毁；跑 cleanup；**配置省略 id 不会触发此路径** |
| `mount` | 幂等；默认复用实例；`remount:true` 才先毁再建 |

**配置语义：** `ORBIT.widgets` 中**未列出**的已挂载 id → **不更新该实例**（不销毁、不强制改 visible）。只有 `destroy(id)` 或 `remount` 才释放。

**可见性目标：** Runtime 只调用 instance 的 `setVisible` 或 `getVisibilityTargets()`（返回需同步隐藏的节点列表）。**禁止** Runtime 内 `if (id === "music")` 操作 `#mp-dock-list`。

### 2.4 契约瘦身

**必选 Definition：** `id`、`label`、`mount(ctx) → Instance`  
**Instance 必选：** `destroy()`  
**Instance 可选：** `root`、`setVisible`、`getVisibilityTargets`、`getSnapshot`  

**ctx 必选：** `id`、`config`、`storage`、`cleanup`、`on`/`emit`、`actions.setVisible`  
**可选：** 完整 slots、dock/setPosition（Host 级）

### Phase 1 — Contract + 测试入口

| 项 | 状态 |
|----|------|

### Phase 3 — Music Adapter（portal 所有权）

| 项 | 状态 |
|----|------|
| 资源清单：pointer、pjax、Observer、Audio、timer、**本实例创建的 portal** | ☐ |
| 每项 `cleanup`；`destroy` 可重入 | ☐ |
| **Portal 规则：** 只移除/解绑 **当前 instance 创建时登记** 的节点（如该次挂载创建的 dock list）；**禁止**按全局固定 id 无条件 `remove()` 可能不属于自己的节点 | ☐ |
| 不改手势阈值、不改 Dock 叙事、不大挪模板 | ☐ |
| 手测：拖拽、磁吸、Dock、歌单方向、移动卡片、长按 Launcher | ☐ |

**完成标准：** 销毁后无双音频/幽灵监听；交互关键项通过。

## 五、顺序（不可跳）

```text
0 Freeze
→ 1 Scope + test:unit 变绿
→ 2 Clock destroy 变绿
→ 3 Music Adapter（含 portal 所有权）
→ 4 Runtime API（省略≠销毁；去 music 特判）

→ 7 性能（有证据）

```
